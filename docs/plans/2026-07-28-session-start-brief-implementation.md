# Session-start brief implementation plan

> Execute in the isolated `codex/session-start-brief-redesign` worktree. Keep
> every production change behind a focused RED test and commit each completed
> task separately.

**Goal:** Replace the fake no-topic context search and prompt-owned status file
with a Space-owned Brief that agents can read through MCP and update through
handoff.

**Architecture:** `wenlan-core` owns Brief state and optimistic item mutations;
`wenlan-server` owns HTTP composition, one-time Markdown import, and receipt
projection; `wenlan-mcp` exposes the read-only `brief` tool; the CLI provides
the write path used by Claude and Codex handoff skills. The deprecated
`context` tool remains callable for known legacy clients but leaves
`tools/list`, so replacing it with `brief` keeps the visible local MCP surface
at 29 tools.

**Non-goals:** No wenlan-app changes, task-manager features, persisted
workstreams, automatic item aging, or cross-Space brief search.

**Files**

### RED

Add serialization tests that require:

- `Brief`, `BriefItem`, and `BriefItemState::{Active, Backlog}`
- a read response that distinguishes `space_not_resolved`,
  `brief_not_created`, and `ready`
- item mutation variants for add, edit, move, gate, and complete
- `expected_version` on every existing-item mutation
- a result receipt separating applied mutations from conflicts

Add a migration test that opens a version-99 database and proves the next
migration creates:

```sql
briefs(
  space_id TEXT PRIMARY KEY REFERENCES spaces(id) ON DELETE CASCADE,
  last_session_summary TEXT NOT NULL DEFAULT '',
  last_handoff_at INTEGER,
  version INTEGER NOT NULL DEFAULT 1,
  updated_at INTEGER NOT NULL
)

brief_items(
  id TEXT PRIMARY KEY,
  space_id TEXT NOT NULL REFERENCES spaces(id) ON DELETE CASCADE,
  text TEXT NOT NULL CHECK(length(trim(text)) > 0),
  state TEXT NOT NULL CHECK(state IN ('active', 'backlog')),
  added_at INTEGER NOT NULL,
  gate TEXT,
  version INTEGER NOT NULL DEFAULT 1,
  updated_at INTEGER NOT NULL
)
```

The test must also prove that a Space rename preserves the Brief through its
stable `space_id`, and Space deletion cascades.

### GREEN

Implement only the shared types and the next numbered migration. Keep schema
DDL and row decoding in `db/brief.rs`; `db.rs` should contain only the module
declaration, migration call, and schema-version bump.

Before final integration, rebase on current `origin/main`. If another merged
change has consumed the planned migration number, renumber this migration and
its fixtures rather than creating a collision.


## Task 2: Implement item-level Brief reads and mutations

**Files**

- Modify: `crates/wenlan-core/src/db/brief.rs`
- Modify: `crates/wenlan-core/src/db/brief_test.rs`

### RED

Add focused tests for:

1. Reading a Space with no Brief returns `brief_not_created` without writing.
2. The first explicit update creates the Brief.
3. Add assigns a stable item ID.
4. Edit, move, gate, and complete require the current item version.
5. Completing an item removes it from subsequent reads.
6. Non-overlapping mutations apply in one request.
7. A stale same-item mutation returns a conflict and leaves the newer row
   unchanged while unrelated mutations still apply.
8. Replaying the same caller/operation ID returns the stored receipt instead of
   duplicating an added item.
9. Reusing an operation ID with a different request digest is rejected.

Include a positive control that would fail if the stale mutation were allowed
to overwrite the row.

### GREEN

Implement:

- `MemoryDB::get_brief_by_space_name`
- `MemoryDB::apply_brief_update`
- per-item compare-and-swap updates
- partial conflict receipts
- idempotent retries through the existing `operation_receipts` table

Use one database transaction per update request. New item IDs are generated by
the daemon. Do not add daemon-side fuzzy text matching.

### Verify

```bash
cargo test -p wenlan-core db::brief_test
```
