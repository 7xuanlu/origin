# M5 — the ceremony (PR-D)

Advances `truth_cutover_generation` from 0 to 1, turning the truth-exposure
contract on for the first time. PR-B (#408, `f29c2c54`) shipped the substrate;
PR-C (#409, `3932e3d5`) shipped the adapters. Neither enforces anything: at
generation 0 `page_visibility` answers `Full` for every page, so every adapter
is the identity function.

Advancing is **destructive**. The projection pass deletes the `.md` of every
page the contract hides, out of the user's real vault. Everything below exists
so that deletion cannot outrun the read gates.

## Decisions taken 2026-07-29

Four forks were put to the user with evidence; all four took the recommended
option.

| # | Decision | Chosen |
|---|---|---|
| 1 | How to close `/api/activities` | **Redact at read time** |
| 2 | `GET /api/memory/entities/{id}` | **Demote — it is mislabeled** |
| 3 | How much ceremony debt lands before the flip | **Minimum-safe** |
| 4 | How an operator advances the generation | **CLI with mandatory dry-run** |

### 1 — `/api/activities`: redact at read time

The title is baked into the free-text `detail` column at **write** time by four
sites (`post_write.rs:2078`, `:2163`, `:2918`, `post_ingest.rs:356`), and
`agent_activity` (`db.rs:3992-4000`: `id, timestamp, agent_name, action,
memory_ids, query, detail`) has no page reference at all — `memory_ids` holds
memory ids. So a write-path fix leaves every existing row leaking, and there is
nothing to key a per-page filter on.

Chosen fix: when the resolved grant is not `Full`, blank `detail` on any
`page_*` action. This is **fail-closed without identifying the page** — the
route does not need to know *which* page a row names in order to refuse to
show the sentence. It covers historical rows the moment it ships, needs no
migration, and destroys nothing.

Rejected: adding a `page_id` column plus a migration that nulls historical
`detail` (schema change, and the migration permanently destroys existing
activity text); and demoting the route (a deliberate hole).

### 2 — `GET /api/memory/entities/{id}`: demote

The manifest justifies page-bearing with `"Entity.name = pages.title (M3)"`
(`truth_manifest.rs:199`). The evidence says that is a conflation:

- The field reads from `pages` only when the per-consumer
  `entity_reader_cutover` for `"scoped_entities"` is on
  (`db/scoped_entities.rs:99-131`, gated by `reader_uses_entity_pages`,
  `db.rs:17648-17701`). It is **default OFF**, so in production the field is
  plain `entities.name` and no `pages` row is touched.
- Even with the cutover on, `pages.title` for a `kind='entity'` shadow is a
  byte-for-byte mirror of `entities.name`, kept in sync at write time by
  `update_entity_shadow_page` (`db.rs:9945-9968`), not independently authored
  page prose.
- Observations and relations come from `observations` / `relations`, never
  `pages` (`db/scoped_entities.rs:146-180`).
- Real page readers already exclude `kind='entity'` shadows (`db.rs:89481`).

So the route exposes the entity's own name, duplicated into a shadow row for an
unrelated migration. **Re-verify this trace inside the PR before committing the
demotion** — a demotion is a security-relevant edit and secondhand evidence is
not enough to land one.

### 3 — Minimum-safe scope

Build before the flip:

- **The write fence.** Pages are projected at runtime (`post_write.rs:2852`),
  so without a fence a page written mid-ceremony slips past the pass that just
  ran. Fully specified at `docs/plans/2026-07-27-m5-migration-state-machine.md:20-273`
  (`(epoch, phase)`, cutover lease); no code exists — `set_truth_cutover_generation`
  (`db/truth_exposure.rs:280-283`) is a bare `set_app_metadata` write with no
  fence or CAS.
- **The export permit.** Export writes prose to disk outside the HTTP gate and
  currently hardcodes its grant: `export/knowledge.rs:520` passes
  `TruthGrant::Automatic` directly. No `TruthPermit` type exists anywhere.

Demote rather than build:

- **Page-map** (`GET /api/pages/{id}/map`) drops to `MarkerShape::None` so it
  refuses rather than half-serves. `handle_get_page_map`
  (`page_map_routes.rs:160-185`) returns raw nodes/edges with zero visibility
  filtering today, and hiding a node in a graph is a design problem — incident
  edges are keyed by node ids, not page ids — with no design yet.

Defer:

- **Typed `AdapterId` / `TruthResponse<T>`** with a private constructor. Today
  `adapter` is `&'static str` on all three reader structs (`truth_manifest.rs:111`,
  `:124`, `:134`), so a missing adapter is a runtime string, not a compile
  error. Real ergonomics win, not a safety gate for this flip.

### 4 — `wenlan truth cutover`, dry-run mandatory

Nothing in production reaches `set_truth_cutover_generation` today: every
caller is a test (`db/truth_exposure_test.rs`, `export/projection_invariant_test.rs`),
and no route, CLI command, migration, or startup path touches it. An ordinary
upgrade therefore cannot advance the generation — but the ceremony has to build
the surface that does.

`wenlan truth cutover --dry-run` lists every page that would be hidden and every
`.md` that would be deleted from the vault. `--apply` refuses unless a dry-run
has been produced for the same state. Rejected: an HTTP admin route, which would
make a vault-deleting operation reachable by anything that can reach :7878,
including agents.

### What stage 3 built

`(epoch, phase)` in `app_metadata` under `truth_cutover_fence`, swapped by a
single conditional SQL statement rather than a read-then-write. `begin_cutover`
mints a `CutoverLease` (private field, so it cannot be fabricated);
`commit_cutover` writes the generation and *then* releases the fence, which is
the §7.5 ordering invariant; `abort_cutover` returns to `off` **at a new epoch**,
which is what makes the ABA test pass.

`page_write_permit` is where writers feel it: while a ceremony prepares, every
page write is refused. An unreadable fence propagates as an error rather than
defaulting — "inert" for a fence means letting writers through, and that is
exactly wrong when the ceremony state is indeterminate.

The PR-B tooth `the_cutover_setter_has_no_production_caller` is amended, not
deleted, exactly as its own failure message instructed: it now allows the single
call in `commit_cutover` and fails on a second one in the same file.

### What stage 4 found

The plan above assumed export was the gap. The real gap was narrower and worse:
**`enforce_projection_directory_invariant` has exactly one production caller,
at daemon startup** (`wenlan-server/src/main.rs`). There is no sweep behind an
ungated write, so a page re-projected past the permit sits in the user's vault
until the next restart.

Two production paths did exactly that:

- `post_write.rs` `regenerate_page_projection_cas` — the receipted lint/repair
  operation. Now takes the permit **before** the connection mutex (the closure
  below it holds that mutex, and the permit needs the same connection) and
  **refuses** without one: telling a caller "repaired" while the file was never
  rewritten is worse than an error.
- `sources/page_watcher.rs` — re-projects from DB truth when a user's edit
  touched the protected Sources block. Now **skips** without a permit, which is
  the honest response for an ambient reaction to a file the user touched.

The projection invariant's own hardcoded `TruthGrant::Automatic`
(`export/knowledge.rs`) is correct and stays: the reader there is a filesystem,
which declares no contract and carries no human gesture.

## Not in this PR

- Typed `AdapterId` / `TruthResponse<T>` (deferred above).
- Page-map hiding as a graph transformation (demoted above; needs a design).
- Rewriting the four `detail` write sites to carry a page reference — the
  read-time redaction makes it unnecessary for safety, and it stays available
  later if the activity log should keep showing titles to permitted readers.

### What stage 5 built, and a tooth that had to be rewritten

`wenlan-server truth-cutover [--generation N] [--apply]` — a hidden maintenance
subcommand on the daemon binary, mirroring `backfill-stale-pages`: refuses while
the service is registered or a daemon answers, takes the data-root lock, opens
the DB directly.

Decision 4 said "CLI, not an HTTP admin route". This is stricter than the CLI
would have been: the `wenlan` CLI talks HTTP, so putting it there would have
needed exactly the route the decision rejected. On the daemon binary it is
reachable only from a shell on the machine, and only with the daemon stopped.

The ordering lives in `KnowledgeWriter::run_truth_cutover`, not in the command,
so it is testable in core: take the lease → evict the files → commit the
generation → release the fence → reconcile.

**Two teeth shipped in the first draft did not hold, and were rewritten.** Both
passed under the mutation they were supposed to catch:

- The happy-path ceremony test could not tell directory-first from commit-first,
  because the reconcile pass afterwards deletes the same files either way. The
  ordering is only observable when the directory work *fails*, so the
  replacement forces that (read-only projection root, unix-only) and asserts the
  generation still reads 0 — a committed generation with the prose still on disk
  is the exact "false trust" state directory-first exists to prevent.
- The digest test changed the eviction list along with the projection, so a
  digest over the eviction list alone would still have caught it. The
  replacement adds a *supported* page between plan and apply, which leaves the
  eviction list byte-identical and moves only the digest.
